# 04. 비판적 리뷰

## 주요 기여 (Contributions)

1. **형식 언어:** Vega-Lite, 데이터 스키마, 사용자 과업을 logical facts로 표현한다.
2. **지식 베이스:** well-formedness, expressiveness, preference를 hard/soft constraints로 구현하고 오픈 소스로 공개했다.
3. **학습 방법:** 실험 결과를 순위 쌍으로 바꾸고 RankSVM으로 soft-constraint weight를 학습한다.
4. **실증:** APT와 CompassQL을 재구현해 표현력과 성능을 보이고, Draco-Learn으로 서로 다른 출처의 실험 데이터를 통합할 수 있음을 보였다.

## 강점

- **관심사의 분리:** "무엇이 좋은 디자인인가"(지식)와 "어떻게 찾는가"(검색)를 분리했다. 검색은 Clingo에 맡긴다.
- **간결성과 유지보수성:** CompassQL 4,324줄이 제약 180개로 줄었다. 같은 규칙이 JS 14줄에서 ASP 1줄로 줄어든 예도 있다.
- **확장성:** 새 데이터 속성(kurtosis), 새 규칙, weight 업데이트를 따로 배포할 수 있다. 새 규칙의 weight를 0으로 시작하면 기존 동작이 유지된다.
- **원리 있는 weight 설정:** 손으로 튜닝할 때 생기는 "국소 변경, 전역 효과" 문제를 데이터 기반 학습으로 바꿨다.
- **이론적 토대:** MLN으로 해석할 수 있다. 최적 완성 = MAP 추론이라는 설명으로 비용 모델에 확률적 의미가 생긴다.
- **겸손한 "최적" 정의:** 절대적인 최선이 아니라 정의된 선호 아래에서의 최적이라고 명시했다.

## 한계와 비판 포인트

1. **학습 데이터가 좁다.** 순위 쌍 대부분(약 1,100쌍)이 Kim & Heer의 산점도 12종에서 나왔고, Saket은 10쌍뿐이다. 그래서 Draco-Learn은 **설계 공간을 실험 범위로 제한한 상태**에서만 평가됐다. 전체 Vega-Lite 공간에서 CQL보다 낫다는 증거는 없다.
2. **평가 지표의 의미:** 93% 대 65%는 같은 실험 분포에서 뽑은 테스트 쌍에서의 정확도다. hand-tuned 모델은 task 관련 weight가 0이라 애초에 과업을 구분할 수 없으니 불리한 비교일 수 있다. 사용자 연구는 없다.
3. **규칙(구조)은 여전히 사람이 만든다.** weight만 학습하고 soft constraint 자체(특징)는 전문가가 작성한다. 저자들도 ILASP 같은 규칙 학습을 향후 과제로 든다.
4. **선형 비용 모델:** 비용은 위반 횟수 × weight의 선형 합이다. 제약 간 상호작용은 규칙을 새로 정의해야만 표현할 수 있다.
5. **설계 공간이 제한적이다:** 단일 뷰와 facet만 다룬다. 필터, 정렬, 상호작용, 다중 뷰, 레이어는 빠져 있다.
6. **과업 모델이 단순하다:** value와 summary 두 가지뿐이다. 실제 사용자의 과업은 대개 알 수 없다(저자들도 인정함).
7. **저수준 지각 요인:** overplotting, 색 대비처럼 데이터 값에 따라 달라지는 요인은 고수준 명세에 드러나지 않는다.
8. **표기상 사소한 문제 (리뷰어 관점):**
   - §6.2에서 `:- single_channel(C), 2 { channel(_,C) }.`를 "prefer not to"라고 설명하지만, 이 규칙은 hard constraint(`:-`)다.
   - §5에서 "linear regression … minimizing the hinge loss"라고 표현했지만, 실제로는 쌍 차이 벡터에 대한 선형 SVM **분류**다.
   - 손실 함수의 합 상한이 PDF에서 k로 보인다. 앞의 1/n과 맞추려면 n이어야 자연스럽다(텍스트 추출 기준이므로 원문 그림으로 재확인 필요).

## 개념 노트의 "다시 확인할 질문"에 대한 답

| 질문 | 답 (근거) |
|---|---|
| marks, fields, channels를 어떻게 표현하는가? | `mark/1`, `encoding/1` + `channel/2`, `field/2`, `type/2`, `aggregate/2`, `bin/2` 등. 채널마다 predicate를 두지 않고 일반화했다 (§4.1) |
| hard/soft는 ASP에서 어떻게 표현되는가? | hard = 머리 없는 integrity constraint `:- body.` / soft = `:~ body. [w]` 또는 `[w@P,E]` (§3, §4.2) |
| 어떤 목적함수와 학습 절차를 쓰는가? | 위반 횟수 feature 차이 x1 − x2에 대한 RankSVM. hinge loss + L2(λ = 0.1). scikit-learn 사용 (§5, §6.3) |
| 실험 결과를 어떻게 weight로 바꾸는가? | (스키마, 과업)별로 묶음 → 시각화 쌍 생성 → Fisher's test p < 0.01인 쌍만 채택 → Clingo로 feature 벡터화 → 학습 (§6.3.1) |
| 한계와 확장 용이성은? | 위 한계 1~7 참고. 확장은 predicate나 규칙을 추가하고 새 weight를 0에서 시작하면 된다. Kim 규칙 구현에 "몇 시간" 걸렸다 (§6.3.1, §7.1) |

## 발표 중 청중과 나눌 토론 질문 (후보)

1. "좋은 시각화"를 weight 하나로 요약할 수 있을까? 미적 요소나 맥락은 어떻게 다룰까?
2. 실험실에서 측정한 정확도와 시간이 실제 분석 상황의 "좋음"을 대표할까?
3. LLM이 차트를 추천하는 지금, 규칙 기반 형식 모델의 가치는 무엇인가? (설명 가능성, 검증 가능성, 일관성)
4. 우리 수업에서 배운 설계 원칙 하나를 Draco 제약으로 써 본다면?
